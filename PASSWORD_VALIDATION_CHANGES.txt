Password Validation Changes
===========================

Purpose
-------
Registration now enforces the required password rules in both the user interface and the backend.

Requirements enforced
---------------------
- At least 8 characters.
- At least one uppercase letter.
- At least one lowercase letter.
- At least one number.
- At least one special character.

Files added
-----------
- shared/password-policy.js
  Shared password requirements and validation helpers used by the frontend and backend.

- api/auth/register.js
  Backend registration endpoint. It validates the password before calling Supabase Auth and returns the missing requirements when validation fails.

Files changed
-------------
- src/components/auth/SignUpModal.jsx
  - Displays missing password requirements while the user types.
  - Blocks invalid passwords before sending the registration request.
  - Sends valid registration requests to /api/auth/register.
  - Restores the returned Supabase session before creating the public user profile row.

- api/_lib/config/env.js
  - Adds backend auth configuration support for SUPABASE_PUBLISHABLE_KEY.
  - Also accepts SUPABASE_ANON_KEY or VITE_SUPABASE_ANON_KEY as fallbacks.

- render.yaml
  - Adds SUPABASE_PUBLISHABLE_KEY to the backend environment variables.

Backend behavior
----------------
- Invalid passwords receive HTTP 400 with a list of missing requirements.
- Invalid passwords do not reach Supabase Auth and should not create an account.
- Valid passwords create the Supabase Auth user and then attempt to create or update the public.users profile row.
- Passwords are sent to Supabase Auth and are not stored as plaintext by this application.

Configuration note
------------------
The backend must have SUPABASE_PUBLISHABLE_KEY configured. The existing VITE_SUPABASE_ANON_KEY value can be used as a fallback.

Validation performed
--------------------
- ESLint passed for the changed JavaScript files.
- Production Vite build passed.
- Password policy assertions passed for the individual requirements.
- Workspace diagnostics reported no errors in the changed source files.

Account deletion
----------------
- Added a Delete account control to the Edit profile modal.
- The user must type Confirm exactly before the delete button is enabled.
- Added POST /api/auth/delete-account, which authenticates the request, deletes the Supabase Auth user, and explicitly removes the public.users row.
- Successful deletion signs the user out and returns them to the landing page.
